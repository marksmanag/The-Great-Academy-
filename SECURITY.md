# Security Policy

## Reporting a Vulnerability

The Great Academy takes security seriously. If you discover a security vulnerability, please report it responsibly.

**Do not:**

- Open a public GitHub issue for security vulnerabilities
- Publish vulnerability details before they are fixed
- Attempt unauthorized access to systems or data

**Do:**

- Report privately to the CODEOWNERS (contact method to be established)
- Provide clear details about the vulnerability
- Include reproduction steps if possible
- Allow reasonable time for response and remediation

## Security Considerations

### Code and Documentation

- All code contributions will be reviewed for security issues
- Documentation should not contain:
  - API keys, tokens, or credentials
  - Private email addresses or personal information
  - Information that could enable unauthorized access
  - Security vulnerabilities or exploitation techniques (without context)

### Data and Privacy

- The Great Academy repository is public
- Treat all contributions as public
- Do not commit sensitive information
- Consider privacy implications of documentation

### Dependencies

- Future code development should manage dependencies carefully
- Use reliable, well-maintained libraries
- Review licenses and security implications
- Report vulnerable dependencies

## Responsible Disclosure

We follow responsible disclosure practices:

1. **Report privately** — Contact CODEOWNERS with details
2. **Allow time to respond** — Typically 90 days before public disclosure
3. **Coordinate timing** — Work with maintainers on release timeline
4. **Provide credit** — Acknowledgment of responsible disclosure
5. **Support remediation** — Help validate fixes if possible

## Security Best Practices

As The Great Academy expands beyond documentation:

- All code will be subject to security review
- Dependencies will be regularly audited
- Access controls will be implemented and documented
- Secrets management will follow industry standards
- Security updates will be applied promptly

## Governance

- CODEOWNERS are responsible for security review
- Security issues are treated with priority
- Decisions about security vulnerabilities are documented
- Patterns and learnings inform security policy

## Questions

For security-related questions that are not vulnerabilities:

- Open an issue labeled `security`
- Contact CODEOWNERS directly
- Review this policy and related documentation

## Future Security Architecture

As The Great Academy develops software systems (including MCP servers and agentic infrastructure):

- Authentication and authorization will be designed and documented
- Encryption will be used for sensitive data
- Audit logging will be implemented
- Security reviews will be part of the development process
- Incident response procedures will be established
